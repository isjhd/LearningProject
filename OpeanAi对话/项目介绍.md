# AI项目

## 介绍

需求背景：售卖额度提供 ChatGLM、ChatGPT 等各类生成式服务。

主要功能：微信登录、支付宝支付、AI聊天

技术架构：前后端分离 + 微服务单体架构 + SpringBoot项目

1. nginx负责反向代理，负载均衡
2. GuavaCache用于缓解数据库压力
4. MySQL用于保障数据的一致性
5. @Scheduled 负责定时任务发现事件
6. EventBus用于解耦事件发送和事件消费
7. 服务部署在docker上

包含什么模块：微信模块、支付宝模块、AI聊天模块、登录鉴权模块、AI账户模块。

（模块如何开发：用户通过决策命令，使用领域对象，通过业务逻辑，产生多个领域事件，过程中调用了一次外部接口）





## 流程

1. 用户登录生成token
2. JWT token校验
3. 支付宝购买对话次数
4. ai聊天









## 扩展点

支付宝一致性保障

背景：先生成订单，返回支付地址给用户，等待用户支付完成，支付宝进行异步回调修改订单状态。

问题：网络波动，服务超时很容易引发数据库订单和支付宝的实际情况不一致的情况

行动：三个定时任务作为兜底补偿(未支付、已支付未发货、超时关单)



aisdk开发

背景：项目对接多家 AI 接口，多厂商接口不统一，维护麻烦。

任务：统一封装底层细节、兼容多版本 API、适配高并发流式对话

行动：

- 参考 MyBatis 工厂 + Session 架构做会话模型，做成只读不能改并且全局唯一。
- OkHttp3 实现网络层 + 事件驱动封装流式应答。
- 适配器模式适配旧版本和新版本。
